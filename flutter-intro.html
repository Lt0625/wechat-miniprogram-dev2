🔵 Flutter 记账 APP

Flutter 跨平台开发 · Dart 语言 · 一套代码 Android + iOS 双端运行 · Provider 状态管理 · Hive 本地持久化
项目概览
基于 Flutter 框架开发的跨平台记账APP，同一套 Dart 代码编译到 Android 和 iOS 两个平台，代码复用率 > 90%。采用 Provider + ChangeNotifier 进行响应式状态管理，Hive 作为轻量级本地 NoSQL 数据库实现纯本地持久化，GoRouter 管理声明式路由。与小程序版功能对齐的同时，利用 Flutter 特性实现 Material 3 动态主题和响应式布局。
开发过程中坚持真机调试（小米设备 ADB 连接），严禁使用模拟器，确保手势交互、性能表现、软键盘行为等均为真实体验。通过 flutter run --profile 进行性能分析，保障 60fps 流畅度。
技术栈
Dart Flutter 3.x Provider + ChangeNotifier Hive (NoSQL) GoRouter Material 3 fl_chart 图表 Android + iOS 双端
技术选型理由
选型理由
Flutter vs React Native 自绘引擎无需桥接，性能接近原生；Dart 强类型+空安全，编译时捕获错误；Widget 组合模式灵活度高于 RN 的组件映射
Provider vs Bloc/Riverpod Provider 是官方推荐方案，学习曲线平缓；ChangeNotifier 模式直觉友好，适合中小型项目；Bloc 过重，Riverpod 编译时安全但学习成本高
Hive vs SharedPreferences/SQLite Hive 是纯 Dart 实现的 NoSQL 数据库，无需原生插件，类型安全的 Box 操作，支持 lazy loading，性能优于 SQLite 的 ORM 开销
GoRouter vs Navigator 1.0 声明式路由，支持深链接、路由守卫、嵌套路由、重定向；Navigator 1.0 命令式 push/pop 难以维护复杂导航栈
架构设计
三层架构
UI 层 (Widget)
展示界面 + 用户交互
⇄
逻辑层 (ChangeNotifier)
业务逻辑 + 状态管理
⇄
数据层 (Hive Box)
本地持久化存储
数据流向：UI 层通过 context.watch<T>() 监听逻辑层数据变化自动重建，通过 context.read<T>() 调用逻辑层方法触发业务操作。逻辑层操作 Hive Box 读写数据，数据变更后调用 notifyListeners() 通知所有监听者刷新 UI。这种模式将 UI 和业务逻辑完全解耦。

Provider 状态管理详解
Provider 是 Flutter 官方推荐的状态管理方案。核心理念是将 UI 和业务逻辑分离——UI 层只负责展示和监听，逻辑层负责数据处理和通知。本项目通过 ChangeNotifier + context.watch/read + notifyListeners 三件套实现完整的响应式状态管理。
Provider 工作机制
UI 层 context.watch<BillProvider>()
→
监听数据变化
→
数据变化 → 自动重建 Widget
UI 层 context.read<BillProvider>()
→
调用业务方法
→
方法内 notifyListeners()
→
所有 watch 的 Widget 刷新
核心代码示例
// 1. Provider 定义（逻辑层） class BillProvider extends ChangeNotifier { List<Bill> _bills = []; // watch 监听的数据 List<Bill> get bills => _bills; // read 调用的方法 void addBill(Bill bill) { _bills.add(bill); _saveToHive(); // 持久化到 Hive notifyListeners(); // 通知所有监听者 } } // 2. UI 层监听 Widget build(BuildContext context) { final bills = context.watch<BillProvider>().bills; // bills 变化时 Widget 自动重建 } // 3. UI 层调用方法 onPressed: () { context.read<BillProvider>().addBill(newBill); // addBill 内部 notifyListeners → 自动刷新 }
watch vs read 关键区别
方法作用使用场景是否触发重建
context.watch<T>() 监听数据变化 build() 方法内，需要根据数据渲染 UI ✅ 是
context.read<T>() 获取 Provider 引用 事件回调（onPressed 等），调用方法 ❌ 否
Provider 注册（main.dart）
void main() async { await Hive.initFlutter(); runApp( MultiProvider( providers: [ ChangeNotifierProvider(create: (_) => BillProvider()), ChangeNotifierProvider(create: (_) => AccountProvider()), ChangeNotifierProvider(create: (_) => ThemeProvider()), ], child: const MyApp(), ), ); }

技术亮点
📱 一套代码双端运行 核心能力
同一套 Dart 代码编译 Android APK 和 iOS IPA，代码复用率 > 90%。Flutter 自绘引擎无需桥接，性能接近原生。
关键点：平台特定代码通过 Platform.isAndroid/iOS 条件分支处理；小米真机 ADB 调试（adb devices + flutter run），禁用模拟器确保真实体验。
🔄 Provider 响应式状态管理 架构设计
ChangeNotifier + context.watch/read，UI 与逻辑完全解耦。watch 监听数据自动重建，read 调用方法不重建，notifyListeners() 广播刷新。
设计原则：build() 内只用 watch 获取数据，事件回调用 read 调用方法。避免在 build() 中误用 read 导致数据变化不刷新。
💾 Hive 纯本地持久化 架构设计
纯 Dart 实现的 NoSQL 数据库，零后端依赖，类型安全的 Box 操作，支持 lazy loading 和加密。
选型优势：无需原生插件，跨平台零适配；比 SharedPreferences 支持复杂对象；比 SQLite 省去 ORM 开销。Hive.box('bills') 直接操作，put/get/delete API 简洁。
🧭 GoRouter 声明式路由 工程实践
声明式路由管理，支持深链接、路由守卫、嵌套路由、重定向。替代 Navigator 1.0 的命令式 push/pop。
优势：类型安全，路由表集中管理，支持 URL 导航，便于维护复杂导航栈。对比 Navigator 1.0 的 push/pop 黑盒操作，GoRouter 的声明式路由可读性更强。
🎨 Material 3 动态主题 视觉体验
ColorScheme.fromSeed() 从种子色生成完整配色方案，支持明暗模式切换，Dynamic Color 动态取色。
实现：ThemeProvider 管理 ThemeMode（light/dark/system），切换时 notifyListeners() 刷新全局主题。Material 3 组件自动适配配色。
🧪 真机调试 + 性能分析 工程能力
严格真机调试（小米设备 ADB），严禁模拟器。flutter run --profile 性能分析，DevTools 监控帧率/内存/Widget重建。
原因：模拟器无法模拟真实手势（滑动/长按）、软键盘遮挡、返回键行为、性能差异。真机调试确保发布前体验一致。
